# 플랜 먼저? 바로 실행?

처음 만드는 잔치 요리라면, 바로 칼부터 들기보다 **레시피를 먼저 훑어보고** 재료와 순서를 확인하죠. 반면 라면 하나 끓이는 데 레시피 회의를 열 필요는 없고요. Claude에게 일을 시킬 때도 똑같은 구분이 필요해요.

**계획을 먼저 보자** — 이런 일일 때예요.

- 파일을 많이 옮기거나 지우는 등 **되돌리기 어려운 일**
- 단계가 많아서 중간에 방향이 틀어지면 곤란한 **큰 일**

이럴 땐 요청 끝에 한 마디만 붙이면 됩니다. "**실행하기 전에 계획 먼저 보여줘.**" 그러면 Claude가 "1번으로 이걸 하고, 2번으로 저걸 하겠습니다"라고 순서를 펼쳐 보여줘요. 마음에 안 드는 부분은 그때 고치면 되니, 일이 벌어진 뒤 수습하는 것보다 훨씬 안전합니다.

반대로 "이 문장 맞춤법 봐줘"처럼 작고 금방 끝나는 일은 계획 단계가 오히려 번거로워요. 그냥 바로 시키면 됩니다.

참고로 터미널의 Claude Code에는 **plan 모드**라는 전용 기능도 있어요. `Shift+Tab`은 누를 때마다 모드가 차례로 바뀌는 단추라서, 한 번 눌렀을 때는 plan 모드가 아니라 다른 모드(확인 없이 자동으로 실행하는 모드)일 수 있어요. 그러니 화면 아래에 **plan**이라는 표시가 보일 때까지 여러 번 눌러서 전환하세요. plan 모드에서는 Claude가 실제로 손대지 않고 계획만 세워서 보여줍니다. 계획이 마음에 들면 그때 승인하면 돼요.

폴더 정리처럼 되돌리기 어려운 일 하나를 골라, 요청 끝에 "실행하기 전에 계획 먼저 보여줘"를 붙여 보내 보세요. 계획에서 고치고 싶은 부분을 하나 찾아 말해 보세요.
